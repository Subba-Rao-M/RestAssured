What are WebServices:

Method of communication between two applications using world wide web.
Web service is collection of operations like search hotel with destinations, search rental cars with destinations, search destination packages for provided details

British Aiways -- Book Ticket - at the end show hotel recommendations from bookhotels.com- 
Britiesh airways developed using java
Book hotel developed using .net
Payment gateway using paypal - paypal requests email and password and then internally performs required operation and sends back response

Hotel.com will provides list of hotels as webservice

Web Service is independent of any programming language 
It works on http protocal

Types of WebServices:

1. Simple object access protocal(SOAP)
2. Representational State Transfer(REST) - Architecture style not protocal

SOAP uses XML and REST uses JSON to send request and response


Simple object access protocal(SOAP):
1. Expects standards or protocal to send and request for response
2. Sending and receiving messages using standard protocal between two applications
3. SOAP uses XML language
4. Soap envelop is root element which has information related to server to hit and also which contains headers and body as child elements
5. Soap fault indicating response with error codes

WSDL - Web service description language and also called as Contract of webservice
WSDL is heart of soap web service
WSDL is a XML document which describes web service
in wsdl file binding provides the list of operations supported by web service
then from operation list for operation name go to Types and check the for operation method what operands required with requirement like data type and if any  validations

http://www.dneonline.com/calculator.asmx?WSDL


Difference between Soap and WSDL

Soap message is a XML document used to transmit the data
WSDL is a XML document used to tell how to connect and make request to your web service

SOAP message is the data you transmit
WSDL is informing you how to transmit and what to transmit

Soap mesage is a structure you apply to transmit the data
WSDL is only to describe how to make the call to the service in first place

REST API Testing:

API - Application programming interface
Client - UI/Front side
Server - Backend - code/databases

IF hotels.com wants to display mariotte hotel for reservation, it will ask for API from mariotte
the technology used by hotels and mariotte are different
Both communicates using API
API works on http request and response
When API hosted on world wide web it is called web service
Representation of data in different format
XML and JSON are used by all programming languages
Only required methods are exposed to Hotels.com by using API
There will be no interaction bewtween Hotels.com and Mariotte
everything happens through API
API is interface or communication protocal between client and server
Rest is light weight protocal compare to soap for communication
Rest is easy to build and maintain
Rest is the arhitectural design to host the APIs


End Point / Base URI - Address where API is hosted on server

HTTP Methods commonly used : PUT, POST, GET and Delete used for CRUD operations

Get: used to retrieve the data from server using URI
NO playload / body required
SHould only retrieve data and no impact on data on server
To send input data in Get request: use query parameter

Post - Used to send data to server using URI
Playload includes the data to be sent
PUT - To update the data in server i.e existing resource and body can include only inputs which needs to be updated

Delete - TO delete the particular record in server


Resouces - APIs or collections which can be accessed from server
https://www.google.com/maps
https://www.google.com/search
https://www.google.com/images

Path Parameter - variable parts of URL path
Used to point to specific resource within a collection
It is like sub resource
like user identified by id
https://amazon.com/orders/1112


Query Parameter - used to sort or filter the resource
Query parameter starts with ?
https://amazon.com/orders?sort_by=2/20/2024
Here is existing resource is filtered
https://www.google.com/search?q=newyork&rlz=1C1GCEA_enIN1137IN1137&oq=newyork


End point or request is constructed as below:

(Base URL)/(Resource)/(Path/Query Parameter)

Headers / Cookies:
Headers represent the meta data associated with the API request and response
Additional details sent with API to process the request
Ex: Authorization details or handshake details like language, content type

If name space is not available in response xpath will not work with xmlholder and value returns null
Proper name space required for xpath in soapui

If name space is not predefined in xml response then follow below procedure:

import com.eviware.soapui.support.XmlHolder
def holder = new XmlHolder(messageExchange.responseContentAsXml)
holder.namespaces["ns1"]='https://maps.googleapis.com/maps/api/place/textsearch/json';
//ns1:Response[1]/ns1:results[1]/ns1:e[1]/ns1:reference[1]

//ns1:Response[1]/ns1:results[1]/ns1:e[1]/ns1:reference[1]
 def actual=holder.getNodeValue("//ns1:Response[1]/ns1:results[1]/ns1:e[1]/ns1:id[1]")
 def ref=holder.getNodeValue("//ns1:Response[1]/ns1:results[1]/ns1:e[1]/ns1:reference[1]")
 context.getTestCase().setPropertyValue("reference",ref)
 def expected =context.getTestCase().getPropertyValue("ID")
assert actual==expected
